ProCloud Documentation

Single-Node, SQLite-First Sovereign Cloud Control Plane built with Go, Podman, systemd Quadlet, Netavark, and Nginx.

Zero Heavy Orchestrators: ProCloud is engineered to transform a single bare-metal server or virtual machine into a complete cloud platform with no Kubernetes, no distributed etcd clusters, no external Redis/RabbitMQ brokers, and zero cloud lock-in.

Architectural Philosophy

Traditional modern cloud setups introduce massive operational complexity and RAM consumption before deploying a single workload. Running etcd, PostgreSQL, Redis, and multi-node orchestrators on a single machine wastes gigabytes of memory and introduces IPC latency over the local network stack.

ProCloud replaces these layers with native Linux kernel facilities and in-process engines:

Embedded SQLite WAL
Zero-latency in-process database with concurrent reader threads, 5000ms busy timeout retry loop, and automated non-blocking WAL truncate checkpoints.
Systemd Quadlet Engine
Workloads compile into native Linux Quadlet unit files (.container, .network, .volume). Containers survive control plane upgrades.
Durable Async Queue
Transactional SQLite job queue with microsecond atomic claims (ClaimNextJob) executing builds and batch workflows completely outside transactions.

Quickstart & Installation

ProCloud compiles into a single, self-contained binary embedding its entire web console and database migration suite.

1. Prerequisites

  • Operating System: Linux (Debian, Ubuntu, Fedora, RHEL) or macOS (with Podman Machine)
  • Go Toolchain: Go 1.22+ installed
  • Container Runtime: Podman 4.5+ or 5.0+ installed and accessible in $PATH

2. Clone & Compile

Terminal — Build Binary 
git clone https://github.com/sanjeevsenapati/procloud.git
cd procloud
go build -o bin/procloud ./cmd/api

3. Launch Control Plane

Terminal — Start ProCloud 
./bin/procloud -port 8080 -db procloud.db
Default Credentials:
Upon first boot, ProCloud automatically applies SQLite database migrations and creates the primary Support Administrator account:
• Username: admin
• Password: admin123
Access the Web Console at http://localhost:8080.

Containers & Pod Management

ProCloud provides complete Podman Desktop capabilities through both an intuitive web interface and secure REST API.

Key Capabilities

Interactive Web Terminal
Execute commands inside any container namespace via POST /api/v1/containers/{id}/exec with ANSI color rendering, history navigation, and 1-click diagnostics (ps aux, df -h, env).
Live Log Streamer
Stream container stdout/stderr in real-time with configurable tail depths (50, 100, 250, 500 lines), regex text search, auto-scroll, and 1-click raw log export.
Top Process Explorer
Inspect active processes running inside container namespaces with PID, PPID, %CPU, %MEM, user, and command strings updated on a 2.5s ticker.
Kubernetes Pod Groups
Deploy multi-container pods sharing network namespaces and storage volumes. Export Pod definitions directly into standard Kubernetes Pod YAML via podman generate kube.

Interactive Container Terminal (PTY Attached)

ProCloud replaces primitive one-shot command runners with a host-native, bi-directional pseudo-terminal (PTY) session attached directly to container namespaces over WebSockets.

Architecture: Host PTY to xterm.js

Full-Duplex Interactive Shell Engine
When opening the Terminal tab in Container Details, the ProCloud API server upgrades the HTTP connection to a WebSocket (/api/v1/containers/{id}/terminal?token=...) and launches a dedicated host pseudo-terminal (/dev/pts/*) via github.com/creack/pty attached directly to podman exec -it <id> <shell>.
Strict Per-Container Isolation
Every container maintains an independent client-side terminal session, DOM viewport, and command history. Switching between containers seamlessly unmounts the previous container's terminal without screen bleeding or history overlap.
Curses & Interactive Programs
Run interactive console software including top, htop, vi, nano, less, Python REPL, and interactive bash/sh scripts with full cursor positioning and ANSI colors.
Dynamic Window Resizing
Viewport dimensions calculated by xterm-addon-fit are automatically synchronized with the host PTY via pty.Setsize, guaranteeing accurate wrapping and column geometry.
Zero External CDN Overhead
Production-grade xterm.js and xterm-addon-fit.js are embedded directly in the single ProCloud executable under /vendor/xterm/ for 100% offline, zero-latency execution.

Build & Deploy (GitOps CI/CD)

Automate container builds and deployments using declarative deploy.yml manifests and systemd Quadlet unit compilation.

Sample deploy.yml Manifest

deploy.yml 
apiVersion: procloud.io/v1alpha1
kind: Deployment
metadata:
  name: web-api
spec:
  replicas: 2
  image: docker.io/library/nginx:alpine
  ports:
    - hostPort: 8080
      containerPort: 80
  resources:
    limits:
      cpu: "1.0"
      memory: "512MB"
  ingress:
    domain: api.procloud.internal
  healthCheck:
    path: /healthz
    intervalSeconds: 10
Immutable Releases & 1-Click Rollback: Every deployment creates an immutable release snapshot capturing the Git commit SHA, OCI image digest, manifest YAML, and compiled Quadlet unit. Rolling back to a previous version executes in under 500ms without needing an image rebuild.

Networking & Authoritative DNSaaS

ProCloud includes a built-in Software Defined Network (SDN) powered by Netavark bridge networks and an authoritative RFC 1035 UDP DNS daemon running natively on port 1053.

DNS Zone Types

Private VPC Zones
Internal hosted zones (e.g., corp.internal) bound to private VPC subnets. Resolves microservices without exposing endpoints to public networks.
Public Authoritative Zones
RFC 1035 compliant authoritative DNS resolution supporting standard resource records: A, CNAME, TXT, SRV, SOA, and MX with sub-millisecond query response times.
Terminal — Query Authoritative DNS Server 
dig @127.0.0.1 -p 1053 web.corp.internal A

Load Balancers & SSL/TLS Termination

High-performance Layer 4 (TCP) and Layer 7 (HTTP/HTTPS) reverse proxying with weighted round-robin backend pools and automated SSL management.

3-Option SSL/TLS Architecture

1. ProCloud Sovereign CA
Generates self-signed sovereign X.509 certificates on-the-fly for immediate HTTPS termination with zero configuration.
2. Attach from Vault
Attach pre-existing TLS certificate secrets stored securely in ProCloud's encrypted Secrets Vault.
3. Custom Certificate Upload
Upload custom PEM certificate chains and private keys with automatic validation and hot storage into Secrets.

Persistent Storage & Volumes

Manage durable local storage volumes for stateful applications (databases, message queues, blob caches). Supports local drivers, mount path inspection, quota tracking, and automatic Quadlet volume attachments.

Secrets Vault

Secure encrypted storage for API keys, passwords, database credentials, and TLS certificates. Secrets can be mounted as environment variables or injected as memory-backed files inside container workloads.

Cron Schedules & Background Jobs

A native, zero-dependency cron scheduling and batch processing engine backed by durable SQLite queueing.

Key Capabilities

Standard 5-Part Cron & Macros
Supports standard cron expressions (*/15 * * * *, 0 2 * * *) and macros (@hourly, @daily, @weekly) with next-run evaluation.
Ephemeral Container Execution
Dispatches short-lived Podman containers (--rm) with environment variables, volume bindings, and resource constraints.
Combined Log & Exit Code Capture
Captures stdout/stderr outputs and numerical exit codes (0 for success, non-zero for failure) persisted directly into SQLite.
Concurrency & Manual Triggers
Enforces concurrency policies (Forbid / Allow) and provides immediate 1-click manual execution ("Run Now").

SQLite WAL Coordinator & Hot Backups

ProCloud continuously monitors SQLite Write-Ahead Logging (WAL) journal files to maintain sub-millisecond query performance and ensure automated zero-downtime backups.

Automatic WAL Truncation
Background monitor samples journal size every 30 seconds. Executes passive checkpoints during quiet windows and truncate checkpoints when journal size exceeds 20MB.
Non-Blocking Hot Backups
Executes zero-downtime backups using SQLite's native VACUUM INTO 'backup.db' without acquiring table locks or blocking reader threads.

Multi-Tenant Organizations & RBAC

Multi-tenant boundary enforcement with resource quotas (max CPU, RAM, storage, workloads) across 4 role tiers:

Role Scope Capabilities
Super Admin (admin) Global (Platform-wide) Full administrative authority across all tenants, nodes, WAL checkpoints, and cluster secrets.
Org Admin (org_admin) Tenant Bound Manage team members, workloads, quotas, and certificates within their assigned organization.
Developer (developer) Tenant Bound Deploy containers and pods, build images, trigger batch jobs, and access web terminals.
Viewer (viewer) Tenant Bound Read-only access to metrics, dashboards, container logs, and inspect views. Mutation calls denied (403).

RESTful API Reference

All API calls require authentication via JWT Bearer token (Authorization: Bearer <token>).

Method Endpoint Required Role Description
POST /api/v1/auth/login Public Authenticate user credentials and receive JWT Bearer token.
GET /api/v1/auth/me Authenticated Retrieve current session identity, organization, and role permissions.
GET /api/v1/containers Viewer List containers with real-time status, image tags, and port publishings.
POST /api/v1/containers/{id}/exec Developer Execute interactive command inside container namespaces.
GET /api/v1/dns/zones Viewer List authoritative and private hosted DNS zones.
POST /api/v1/dns/zones Developer Create a new private VPC or public authoritative DNS zone.
GET /api/v1/schedules Viewer List configured cron schedules and next upcoming run timestamps.
POST /api/v1/schedules Developer Create a scheduled container or workflow cron job.
POST /api/v1/schedules/{id}/run Developer Immediately trigger a scheduled job ("Run Now").
GET /api/v1/jobs/{id}/logs Viewer Retrieve execution output, exit code, and timestamps for a job run.
GET /api/v1/database/status Super Admin Retrieve SQLite WAL journal size, active connections, and integrity state.
POST /api/v1/database/backup Super Admin Trigger a non-blocking hot online backup using SQLite VACUUM INTO.
